# Tennis Point Strategy with Reinforcement Learning

## Overview/First Impressions
The goal of this mini-project was to use classical RL algorithms to learn tennis rally shot selection.
This helped me practice and deeply understand algorithms crucial to the basics of RL, such as MC prediction/control, Q-learning, and TD(lambda)/Sarsa(lambda). I particularily enjoyed implementing TD/SARSA using the backward implementation method with eligiblity traces. I found this approach to solving the credit assignment problem pretty cool and interesting to think about. I like being able to update all visited states and state/action pairs online. The emergent behavior that occured when watching the agent link features like being in an attacking state to a more aggressive shot was the highlight of the experiment. This project helped me understand how and why these backbone algorithms work. 


## Environment 
The environment models one tennis point as a rally. At each step, the agent choses a shot, the rally state changes, and the point eventually ends with a win or loss.

The state keeps track of:
- ball position
- player balance
- opponent balance
- stamina
- pressure
The available actions are:
-crosscourt
-down_the_line
-heavy_topspin
-drop_shot
-defensive_slice

Each shot has different probabilities of winning the point, making an error, or continuing the rally. The environment also gives small shaping rewards for good tactical situations, like being in an attacking position or putting the opponent on defense. Episodes end on a win/loss or when the rally reaches the max shot limit. 


## Control Methods

- Monte Carlo control:
Easy to understand algorithm that repeatedly runs trajectories in the environment, observes the reward, and incrementally calculates the mean reward of each visited state using the discounted reward sum Gt.
Eqn: Q(s,a) <- Q(s,a) + $\alpha$(Gt - Q(s,a)) Where $\alpha$ is the learning rate, and Gt is the discounted return.

- Q-learning:
Optimistic update algorithm that uses bootstrapping and off-policy learning to do online-updates on the action-value function. It decides which  state-action pairs to update based on the trajectory generated by following a behavorial policy, however, when updating, the target is the reward + the discounted value of MAX value you can get from the next stateby choosing the optimal action. This makes this algorithm considered offline learning. This means the updates to Q are larger than the updates that come from SARSA.
Eqn: $Q(S_t, A_t) \leftarrow Q(S_t, A_t) + \alpha \left[R_{t+1} + \gamma \max_a Q(S_{t+1}, a) - Q(S_t, A_t)\right]$ Where $\alpha$ is the learning rate.

- SARSA($\lambda$):
Update algorithm that uses bootstrapping and eligiblity traces to do online-updates on the action-value function. $\lambda$ is a chosen parameter, a larger $\lambda$ means that the trace of older states is closer to that of more recently visited states. A smaller $\lambda$ means more recently visited states are given more impact. Sarsa(0) means that $Q(S_t, A_t)$ is updated solely based on the reward from taking action a in state s and $Q(S_t+1, A_t+1)$ Sarsa(1) is equivalent to Monte Carlo control. It takes actions based on the policy being learned, making it an on-policy learning method. The most interesting part of this algorithm are the eligibility traces which gives each state-action pair a value that increments when that state-action pair is visited and decays over time, and thus can be used to denote credit based on frequency and recency.
EQNs:
The TD error is:

$$
\delta_t = R_{t+1} + \gamma Q(S_{t+1}, A_{t+1}) - Q(S_t, A_t)
$$

The eligibility trace for the current state-action pair is incremented:

$$
E(S_t, A_t) \leftarrow E(S_t, A_t) + 1
$$

Then every state-action pair is updated in proportion to its eligibility trace:

$$
Q(s,a) \leftarrow Q(s,a) + \alpha \delta_t E(s,a)
$$

Finally, all eligibility traces decay:

$$
E(s,a) \leftarrow \gamma \lambda E(s,a)
$$

If the next state is terminal, the TD error becomes:

$$
\delta_t = R_{t+1} - Q(S_t, A_t)
$$

## Experiment
The main experiment tests how different values of $\lambda$ affect SARSA($\lambda$) performance. I fixed the learning rate at $\alpha$ = 0.01. Then I trained sarsa($\lambda$) using $\lambda$ = [0.0, 0.1, 0.2, ..., 1.0]. For each $\lambda$ value, the agent was trained for 120,000 episodes and evaluated for 1000 episodes. To reduce randomness, each $\lambda$ was averaged across 3 random seeds. 

Performance was measured using:
- win_rate
- avg_return
